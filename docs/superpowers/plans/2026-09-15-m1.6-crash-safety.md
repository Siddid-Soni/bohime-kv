# M1.6 — Crash Safety Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A crash that tears the tail of a segment file, or interrupts a compaction, must leave the engine openable and correct — recovering to the last intact record and accepting new writes at the right offset.

**Architecture:** `replay` stops at the first undecodable record and reports the valid prefix length instead of erroring. `Engine::open` truncates the *active* segment to that prefix (and rejects a torn closed segment as real corruption). Compaction gains a commit point: the merged segment and its hint are written to `.tmp` files, a `compaction.manifest` is atomically renamed into place to commit the operation, and only then are the renames and unlinks performed — so `open` can finish an interrupted compaction idempotently.

**Tech Stack:** Rust 2024, `std::fs` (`set_len`, `rename`), `crc32fast` (already the record integrity check), `serde` + `bincode` (manifest encoding — both already dependencies of `kv-storage`), `proptest` + `tempfile` (tests), `tracing` (recovery warnings).

**Spec:** `docs/DESIGN.md` §M1.6 and §1.13; roadmap section M1.6 in `docs/superpowers/plans/2026-09-15-bohime-roadmap.md`.

```rust
/// Rebuilds the keydir by decoding records from one segment file, in order,
/// and returns the byte length of the prefix that decoded cleanly.
///
/// Decoding stops at the first record that fails — truncated or checksum
/// mismatch, which are the two shapes a half-written record takes — rather
/// than erroring, because a torn tail is the *expected* state of the active
/// segment after a crash. Everything past the returned length is that tail;
/// the caller decides whether to truncate it (active segment) or reject the
/// open (a closed segment, where a tear means real corruption, not a crash).
///
/// A tombstone removes its key from the index instead of inserting it;
/// whichever record for a key is replayed last wins. Callers must replay
/// segments in ascending `SegmentId` order for that to be correct across the
/// whole log, not just within one file.
fn replay(mut file: &File, segment_id: SegmentId, index: &mut HashMapIndex) -> io::Result<u64> {
    file.seek(SeekFrom::Start(0))?;
    let mut buf = Vec::new();
    file.read_to_end(&mut buf)?;

    let mut offset = 0u64;
    let mut rest = &buf[..];
    while !rest.is_empty() {
        let Ok((record, consumed)) = Record::decode(rest) else {
            break;
        };

        if record.is_tombstone {
            index.remove(&record.key);
        } else {
            index.insert(record.key.clone(), ValueLoc { segment_id, offset, len: consumed as u32 });
        }

        offset += consumed as u64;
        rest = &rest[consumed..];
    }

    Ok(offset)
}
```

## Task 2: Make compaction crash-safe

**Files:**
- Modify: `crates/kv-storage/src/engine.rs:237-330` (`compact`, `apply_compaction`), `engine.rs:134-171` (`open`), `engine.rs:38-59` (hint writing)
- Test: `crates/kv-storage/src/tests/engine.rs`

**Interfaces:**
- Consumes: `replay` from Task 1, `CompactionPlan` (unchanged).
- Produces:
  ```rust
  const MANIFEST_NAME: &str = "compaction.manifest";
  #[derive(serde::Serialize, serde::Deserialize)]
  struct CompactionManifest { new_id: Option<SegmentId>, old_ids: Vec<SegmentId> }
  fn read_manifest(dir: &Path) -> io::Result<Option<CompactionManifest>>;
  fn write_manifest(dir: &Path, m: &CompactionManifest) -> io::Result<()>;   // tmp + rename
  fn finish_compaction(dir: &Path, m: &CompactionManifest) -> io::Result<()>; // idempotent
  ```

**The bug this fixes.** `apply_compaction` reuses the smallest retired segment id for the merged output, calls `set_len(0)` on it, writes the merge, then unlinks the other retired segments. Two failure windows:

1. `set_len(0)` destroys the old contents of that segment *before* the merge is written. A crash mid-write leaves a partial merged segment and no copy of what it replaced.
2. Worse and less obvious: suppose segments `{3,4,5}` are retired and the merge goes to id 3. Crash after the merge is written but before 4 and 5 are unlinked. The next `open` replays 3, then 4, then 5 in ascending order — so the *stale* records in 4 and 5 replay last and win. Overwritten keys revert to their old values; deleted keys come back.

The fix is a commit point. Everything before the manifest rename is invisible; everything after it is replayable to completion.

**Sequence:**
1. Write the merged records to `{new_id}.seg.tmp`.
2. Write the hint to `{new_id}.hint.tmp`.
3. `write_manifest` — tmp + rename. **This is the commit point.**
4. `finish_compaction` — rename both tmp files into place, unlink every `old_id != new_id`, remove the manifest.

A crash before step 3 leaves orphan `.tmp` files and untouched old segments: `open` deletes the orphans and the state is exactly pre-compaction. A crash during step 4 leaves the manifest: `open` replays step 4, which is idempotent (a rename is skipped if its source is already gone; unlinks are best-effort).

```rust
/// Names a compaction that has passed its commit point. Its presence in the
/// directory means the merged segment is fully written under a `.tmp` name
/// and the retired segments may be unlinked; `open` replays the remaining
/// steps before touching anything else, which is what makes an interrupted
/// compaction safe rather than corrupting.
const MANIFEST_NAME: &str = "compaction.manifest";

#[derive(Debug, serde::Serialize, serde::Deserialize)]
pub(crate) struct CompactionManifest {
    /// `None` when every retired segment was entirely dead, so there is no
    /// merged output at all — only deletions to finish.
    new_id: Option<SegmentId>,
    old_ids: Vec<SegmentId>,
}

fn tmp_name(name: &str) -> String {
    format!("{name}.tmp")
}

/// Writes the manifest to a temporary file and renames it into place, so it
/// appears atomically. This rename is the compaction's commit point.
pub(crate) fn write_manifest(dir: &Path, manifest: &CompactionManifest) -> io::Result<()> {
    let encoded = bincode::serialize(manifest)
        .map_err(|e| io::Error::new(io::ErrorKind::InvalidData, e))?;
    let tmp = dir.join(tmp_name(MANIFEST_NAME));
    fs::write(&tmp, encoded)?;
    fs::rename(tmp, dir.join(MANIFEST_NAME))
}

fn read_manifest(dir: &Path) -> io::Result<Option<CompactionManifest>> {
    let path = dir.join(MANIFEST_NAME);
    if !path.exists() {
        return Ok(None);
    }
    let data = fs::read(&path)?;
    match bincode::deserialize(&data) {
        Ok(manifest) => Ok(Some(manifest)),
        Err(e) => {
            // A manifest is written by rename, so a corrupt one should be
            // impossible. Treating it as absent is still the safe reading:
            // the compaction it described is then simply not replayed, and
            // the pre-compaction segments are all still on disk.
            tracing::warn!(error = %e, "ignoring unreadable compaction manifest");
            let _ = fs::remove_file(&path);
            Ok(None)
        }
    }
}

/// Completes a committed compaction. Idempotent: every step is skipped if it
/// has already happened, so it is safe to run on every open and safe to be
/// interrupted and run again.
fn finish_compaction(dir: &Path, manifest: &CompactionManifest) -> io::Result<()> {
    if let Some(new_id) = manifest.new_id {
        let seg = segment_file_name(new_id);
        let seg_tmp = dir.join(tmp_name(&seg));
        if seg_tmp.exists() {
            fs::rename(seg_tmp, dir.join(&seg))?;
        }
        let hint = hint_file_name(new_id);
        let hint_tmp = dir.join(tmp_name(&hint));
        if hint_tmp.exists() {
            fs::rename(hint_tmp, dir.join(&hint))?;
        }
    }

    for &id in &manifest.old_ids {

    fs::remove_file(dir.join(MANIFEST_NAME))
}
```

- [ ] **Step 5: Rewrite `apply_compaction` to use the commit protocol**

Replace `apply_compaction` (currently lines 275-330):

```rust
    /// Writes the plan's live entries into a temporary segment (named for the
    /// smallest retired id, so the merged data still sorts before the active
    /// segment on the next replay) plus its hint file, relocates the index —
    /// skipping any key overwritten since the plan was taken — then commits
    /// with a manifest and finishes the renames and unlinks.
    ///
    /// Nothing before `write_manifest` is visible to a reopen; everything
    /// after it is replayable by `finish_compaction`. That is what keeps a
    /// crash mid-compaction from either losing the merge or letting a stale
    /// retired segment replay over it.
    fn apply_compaction(&mut self, plan: CompactionPlan) -> io::Result<()> {
        let CompactionPlan { old_segment_ids, new_segment_id, entries } = plan;

        let manifest = if entries.is_empty() {
            CompactionManifest { new_id: None, old_ids: old_segment_ids.clone() }
        } else {
            let mut hint_entries = Vec::with_capacity(entries.len());
            let mut relocations = Vec::with_capacity(entries.len());

            let seg_tmp = self.dir.join(tmp_name(&segment_file_name(new_segment_id)));
            {
                let mut file = File::create(&seg_tmp)?;
                let mut offset = 0u64;
                for (key, old_loc, value) in &entries {
                    let record = Record::create(now_millis(), key.clone(), value.clone());
                    let encoded = record.encode();
                    file.write_all(&encoded)?;

                    let new_loc =
                        ValueLoc { segment_id: new_segment_id, offset, len: encoded.len() as u32 };
                    hint_entries.push((key.clone(), new_loc));
                    relocations.push((key.clone(), *old_loc, new_loc));
                    offset += encoded.len() as u64;
                }
                file.sync_all()?;
            }

            write_hint_tmp(&self.dir, new_segment_id, &hint_entries)?;

            for (key, old_loc, new_loc) in relocations {
                self.index.relocate(&key, old_loc, new_loc);
            }

            CompactionManifest {
                new_id: Some(new_segment_id),
                old_ids: old_segment_ids.clone(),
            }
        };

        // Drop every retired segment's file handle before the manifest is
        // applied: `finish_compaction` renames over and unlinks these paths,
        // and a handle kept open here would point at an unlinked inode.
        for id in &old_segment_ids {
            self.segments.remove(id);
        }

        write_manifest(&self.dir, &manifest)?;
        finish_compaction(&self.dir, &manifest)?;

        if let Some(new_id) = manifest.new_id {
            self.segments.insert(new_id, open_segment(&self.dir, new_id)?);
        }

        Ok(())
    }
```

Note the two behavior changes beyond the commit protocol: the merged segment is now written with `File::create` to a fresh `.tmp` path rather than `set_len(0)` on the live file, so the retired data survives until the rename; and the new segment's `File` handle is reopened after the rename, because the pre-rename handle refers to a different inode.

```rust
/// Returns `None` if segment `id` has no hint file, or if the one it has does
/// not parse — callers fall back to `replay`, which rebuilds the same keydir
/// from the segment itself. A hint file is a cache of information the segment
/// already contains, so a bad one is a performance problem, never a
/// correctness one, and must not fail the open.
fn read_hint_file(dir: &Path, id: SegmentId) -> io::Result<Option<HintEntries>> {
    let path = dir.join(hint_file_name(id));
    if !path.exists() {
        return Ok(None);
    }

    let data = fs::read(path)?;
    match parse_hint_entries(&data, id) {
        Some(entries) => Ok(Some(entries)),
        None => {
            tracing::warn!(segment = id, "hint file did not parse; falling back to full replay");
            Ok(None)
        }
    }
}

fn parse_hint_entries(data: &[u8], id: SegmentId) -> Option<HintEntries> {
    let mut entries = Vec::new();
    let mut rest = data;
    while !rest.is_empty() {
        if rest.len() < 16 {
            return None;
        }
        let offset = u64::from_be_bytes(rest[0..8].try_into().unwrap());
        let len = u32::from_be_bytes(rest[8..12].try_into().unwrap());
        let key_len = u32::from_be_bytes(rest[12..16].try_into().unwrap()) as usize;

        if rest.len() < 16 + key_len {
            return None;
        }
        let key = rest[16..16 + key_len].to_vec();

        entries.push((key, ValueLoc { segment_id: id, offset, len }));
        rest = &rest[16 + key_len..];
    }
    Some(entries)
}
```
