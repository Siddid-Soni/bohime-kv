# M3 — Raft Core Implementation Plan

**Goal:** `RaftNode<S: RaftStorage>` implementing Raft figure 2, pure: ticks, messages,
proposals in; `Action`s out. No I/O, no `Instant`, no env-seeded RNG.

**Spec:** `docs/DESIGN.md` §1.5 + §M3; roadmap §M3. Paper figure 2 is the spec,
figures 7/8 are the tests.

## Interfaces (fixed at M3.1 — downstream consumes unchanged)

```rust
pub struct Config { pub id: NodeId, pub peers: Vec<NodeId>,
    pub election_timeout: u64, pub heartbeat_interval: u64, pub seed: u64 }
pub enum Role { Follower, Candidate, Leader }
pub enum Message {
    RequestVote { term: Term, candidate_id: NodeId, last_log_index: LogIndex, last_log_term: Term },
    RequestVoteResp { term: Term, vote_granted: bool },
    AppendEntries { term: Term, leader_id: NodeId, prev_log_index: LogIndex,
        prev_log_term: Term, entries: Vec<Entry>, leader_commit: LogIndex },
    AppendEntriesResp { term: Term, success: bool,
        conflict_term: Option<Term>, conflict_index: Option<LogIndex> },
    InstallSnapshot { term: Term, leader_id: NodeId,
        last_included_index: LogIndex, last_included_term: Term, data: Vec<u8> },
    InstallSnapshotResp { term: Term, success: bool },
}
pub enum Action {
    Send { to: NodeId, msg: Message },
    PersistEntries(Vec<Entry>),
    PersistHardState(HardState),
    ApplyEntries { up_to: LogIndex },
}
pub struct Ready { pub messages: Vec<(NodeId, Message)>,
    pub entries: Vec<Entry>, pub hard_state: Option<HardState>,
    pub committed: Vec<Entry>, pub read_states: Vec<ReadState> }
pub struct ReadState { pub token: u64, pub index: LogIndex }  // M7 fills it; always empty at M3
impl<S: RaftStorage> RaftNode<S> {
    pub fn new(config: Config, storage: S) -> Self;
    pub fn tick(&mut self) -> Vec<Action>;
    pub fn step(&mut self, from: NodeId, msg: Message) -> Vec<Action>;
    pub fn propose(&mut self, cmd: Vec<u8>) -> Result<LogIndex, ProposeError>;
    pub fn ready(&mut self) -> Ready;
    pub fn role(&self) -> Role;
}
```
Deviation from the roadmap: `step` takes the sender's `NodeId`. Anonymous
votes would be double-countable and replication accounting needs to know who
answered; both callers (sim network, tonic peer) know the sender.

## Decisions (locked here)

- `RaftNode` **owns** `storage: S` generic. No lifetimes in sim node tables.
- Election randomization: `rand::SeedableRng StdRng` seeded from `Config.seed`;
  timeout uniform in `[election_timeout, 2*election_timeout)`. No `thread_rng` anywhere.
- Storage errors inside the core are fatal: `.expect("raft storage")`. Rationale:
  `MemStorage` cannot fail; a `BitcaskStorage` IO error means the disk is gone and
  the correct Raft response is process crash + restart from disk (M6 driver does this).
- One term-rules function (`observe_term`) routes ALL inbound terms before dispatch.
- `commit_index`/`last_applied` live in core (not only `HardState.commit_index`);
  `HardState.commit_index` is persisted alongside term/vote whenever commit advances.
- No-op entry on election (M3.5) with empty command; applied like any entry.

## Files

- `crates/kv-raft/src/message.rs` — Config, Role, Message, Action, Ready, ReadState, ProposeError.
- `crates/kv-raft/src/node.rs` — RaftNode, role machine, tick, dispatch, commit/apply, read_index stub (M7).
- `crates/kv-raft/src/log.rs` — consistency check, conflict-hint computation, commit-index math (pure fns over RaftStorage).
- `crates/kv-raft/src/election.rs` — vote-grant decision (pure fn, unit-tested directly).
- `crates/kv-raft/src/replication.rs` — match/next bookkeeping + conflict-hint backtrack (pure fns).
- `crates/kv-raft/src/invariants.rs` — `check_all(nodes) -> Result<(), Violation>`.
- Tests: `tests/message.rs`, `tests/node_tick.rs`, `tests/request_vote.rs`,
  `tests/append_entries.rs`, `tests/commit.rs`, `tests/election_restriction.rs`,
  `tests/invariants.rs`. Test helper: `tests/harness.rs` (`mod harness` with
  3-node cluster driver stepping messages between nodes until quiescence).

## Tasks (one commit each) + named tests

- **M3.1 types:** round-trip every `Message` variant through bincode;
  construct a `Ready` holding entries + hard state + 2 messages.
- **M3.2 tick:** `follower_becomes_candidate_after_exactly_election_timeout`;
  `heartbeat_suppresses_election_over_10k_ticks`; `leader_sends_heartbeats_on_interval`;
  timeouts differ per seed (`randomized_timeouts_differ_across_seeds`).
- **M3.3 RequestVote:** `candidate_with_majority_becomes_leader`;
  `never_votes_twice_in_one_term`; `higher_term_steps_down_in_every_role`;
  `vote_persisted_before_grant` (reopen storage, vote still held).
- **M3.4 AppendEntries:** figure-7 table test `divergent_follower_repair_converges`
  (all six follower logs converge); `conflict_hint_converges_in_two_round_trips`
  vs naive (assert round-trip count on a crafted log).
- **M3.5 commit/apply:** `commits_at_majority_match_index`;
  `figure_8_stale_term_entry_is_not_committed_by_count` (EXACT name);
  `new_leader_appends_noop`; `committed_entries_apply_in_order`.
- **M3.6 restriction:** `stale_log_cannot_win`; proptest `leader_completeness_holds`.
- **M3.7 invariants:** each of election-safety / log-matching / leader-completeness /
  state-machine-safety gets a test that builds a violating state and watches the
  checker fire (`*_violation_is_detected`).
